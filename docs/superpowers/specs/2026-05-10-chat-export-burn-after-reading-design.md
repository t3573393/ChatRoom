# 聊天记录导出与阅后即焚功能设计

> **日期**: 2026-05-10  
> **功能**: 聊天记录导出 + 阅后即焚消息  
> **方案**: 简洁实用型

---

## 📋 功能概述

### 1. 聊天记录导出

**目标**: 让用户能够将聊天记录导出为纯文本文件，便于存档和查阅。

**功能点**:
- 支持导出当前房间或所有房间的聊天记录
- 支持按日期范围筛选导出内容
- 导出格式为 `.txt`，包含时间戳、用户名、消息内容

### 2. 阅后即焚消息

**目标**: 提供私密消息功能，消息在查看后自动销毁，保护隐私。

**功能点**:
- 用户可选择性发送阅后即焚消息
- 消息显示倒计时条，到期自动从所有用户界面消失
- 可配置销毁时间（5/10/20/30 秒）

### 聊天记录导出

#### 触发位置
- 聊天界面顶部工具栏（消息输入框上方）
- 图标按钮 + 文字标签："导出 ↓"

#### 导出模态框

┌─────────────────────────────────┐

### 阅后即焚消息

#### 触发方式
- 消息输入框右侧添加 "🔥" 按钮
- 点击按钮切换状态（未激活 → 已激活）
- 已激活时按钮变红，鼠标悬停显示 "阅后即焚模式"

#### 消息显示样式
```
┌─────────────────────────────────┐
│ 🔥 嗨，这是秘密消息       ████░░ │
│   (5秒后销毁)                   │
└─────────────────────────────────┘
```
- 🔥 图标 + 消息内容
- 进度条显示剩余时间
- 倒计时结束，消息淡出消失

#### 查看后销毁流程
1. 用户点击阅后即焚消息
2. 消息展开显示完整内容
3. 倒计时开始（可配置 5/10/20/30 秒）
4. 倒计时结束，消息从所有用户界面淡出并删除
5. 数据库中同步删除该消息

#### 设置界面
- 个人设置页面添加"阅后即焚默认时间"选项
- 滑块选择：5秒 / 10秒 / 20秒 / 30秒
- 默认值：10秒

## 🔧 技术实现

### 文件结构

**新建文件**:
- `public/app/services/chatExportService.js` - 聊天记录导出服务
- `public/app/services/burnAfterReadingService.js` - 阅后即焚服务
- `views/exportModal.html` - 导出模态框视图
- `views/burnAfterReadingSettings.html` - 阅后即焚设置视图

**修改文件**:
- `public/app/controllers/chatRoomController.js` - 添加导出和阅后即焚逻辑
- `public/app/views/chatRoom.html` - 添加导出按钮和阅后即焚按钮
- `public/app/css/style.css` - 添加相关样式
- `app.js` - 添加导出 API 路由
- `database/db.js` - 添加阅后即焚消息查询和删除方法

### API 设计

#### 聊天记录导出 API

**请求**: `GET /api/export-chat`

**参数**:
```javascript
{
  scope: 'current' | 'all',        // 导出范围
  roomCode: string,                  // 当前房间代码（scope=current时）
  startDate: string (ISO),          // 开始日期
  endDate: string (ISO)             // 结束日期
}
```

**响应**: 
```javascript
// Content-Type: text/plain
// Content-Disposition: attachment; filename="chat-export-2026-05-10.txt"
```

#### 阅后即焚消息标记

**数据库字段**:
```javascript
{
  id: string,
  username: string,
  msg: string,
  msgTime: string,
  roomCode: string,
  isBurnAfterReading: true,       // 阅后即焚标记
  burnDuration: 10,                // 销毁倒计时（秒）
  createdAt: timestamp
}
```

**Socket 事件**:
- `send-message` 增加 `isBurnAfterReading` 和 `burnDuration` 字段
- `message-burned` 事件 - 通知所有用户消息已销毁

### 前端逻辑

#### 导出流程
1. 用户点击"导出"按钮
2. 弹出模态框，选择导出范围和日期
3. 点击"导出"调用 API
4. 浏览器下载 `.txt` 文件

#### 阅后即焚流程
1. 用户点击 🔥 按钮启用模式
2. 输入消息并发送
3. 消息显示时带有 🔥 图标和进度条
4. 其他用户点击查看消息
5. 倒计时开始显示
6. 倒计时结束，消息淡出并从 DOM 移除
7. 收到服务端 `message-burned` 事件确认删除

### 后端逻辑

#### 导出处理
1. 接收导出参数
2. 查询数据库（根据范围和日期筛选）
3. 格式化数据为 TXT 字符串
4. 返回文件下载响应

#### 阅后即焚处理
1. 接收带有 `isBurnAfterReading` 标记的消息
2. 存储消息到数据库，标记为阅后即焚
3. 广播消息给房间内所有用户
4. 客户端显示倒计时
5. 倒计时结束，客户端发送销毁确认
6. 服务端从数据库删除该消息
7. 广播 `message-burned` 事件

## ⚠️ 注意事项

### 阅后即焚

1. **性能考虑**: 大量阅后即焚消息可能增加数据库压力，考虑添加索引
2. **离线用户**: 如果用户在消息销毁时不在线，下次进入将看不到该消息
3. **截图防护**: 无法防止用户截图，仅提供便捷销毁功能
4. **管理员权限**: 管理员可查看所有消息（包括阅后即焚）

### 聊天记录导出

1. **大数据量**: 大量聊天记录导出可能影响性能，考虑添加最大导出限制
2. **敏感信息**: 导出文件可能包含敏感信息，提醒用户妥善保管
