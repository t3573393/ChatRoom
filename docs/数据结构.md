# ChatRoom 数据结构

## 1. 数据库表结构

### 1.1 chat_messages (消息表)

```sql
CREATE TABLE chat_messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,      -- 消息ID
    room_code TEXT NOT NULL,                    -- 房间代码
    username TEXT NOT NULL,                     -- 用户名
    user_avatar TEXT,                           -- 用户头像
    message_type TEXT NOT NULL,                 -- 消息类型: text, image, music, pdf, meme, gif
    message_content TEXT,                       -- 消息内容
    file_info TEXT,                             -- 文件信息 (JSON)
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP, -- 创建时间
    is_burn_after_reading INTEGER DEFAULT 0,    -- 是否阅后即焚
    burn_duration INTEGER DEFAULT 10,            -- 焚毁倒计时(秒)
    status TEXT DEFAULT 'normal'                 -- 状态: normal, edited, recalled
);
```

**索引：**
```sql
CREATE INDEX idx_room_created ON chat_messages(room_code, created_at DESC);
CREATE INDEX idx_messages_content ON chat_messages(message_content);
CREATE INDEX idx_messages_created_at ON chat_messages(created_at);
```

### 1.2 message_edit_history (消息编辑历史表)

```sql
CREATE TABLE message_edit_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    message_id INTEGER NOT NULL,                -- 原消息ID
    old_content TEXT,                           -- 旧内容
    edited_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 1.3 message_delivery_status (消息送达状态表)

```sql
CREATE TABLE message_delivery_status (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    message_id INTEGER NOT NULL,                -- 消息ID
    username TEXT NOT NULL,                     -- 用户名
    status TEXT DEFAULT 'delivered',             -- delivered, read
    delivered_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    read_at DATETIME,
    UNIQUE(message_id, username)
);
```

### 1.4 room_states (房间状态表)

```sql
CREATE TABLE room_states (
    room_code TEXT PRIMARY KEY,                  -- 房间代码
    creator TEXT NOT NULL,                       -- 创建者
    members TEXT,                                -- 成员列表 (JSON)
    mutes TEXT,                                  -- 禁言列表 (JSON)
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## 2. file_info JSON 结构

文件信息存储在 `chat_messages.file_info` 字段中，格式为 JSON：

```javascript
{
    filename: "example.png",          // 原始文件名
    serverfilename: "abc123.png",    // 服务器存储的文件名（可能是完整URL）
    size: "1.2 MB",                  // 文件大小
    type: "image"                    // 文件类型: image, music, pdf
}
```

## 3. 实时消息结构

### 3.1 文本消息

```javascript
{
    id: 123,                         // 消息ID (数据库自增)
    messageId: 123,                  // 兼容前端的messageId字段
    username: "user1",               // 用户名
    userAvatar: "avatar.png",        // 用户头像
    msg: "消息内容",                  // 消息内容
    roomCode: "room1",               // 房间代码
    msgTime: "10:30 AM",            // 显示时间
    createdAt: "2024-01-01T10:30:00Z", // ISO时间戳
    ownMsg: true,                    // 是否自己发送
    status: "sent",                  // sent, delivered, read
    hasMsg: true,                    // 有文字内容
    hasFile: false                   // 无附件
}
```

### 3.2 图片消息


## 6. API 请求/响应结构

### 6.1 文件上传响应

**POST /v1/uploadImage**

Response:
```json
{
    "success": true,
    "message": "Image uploaded successfully"
}
```

## 7. 消息类型枚举

| 类型值 | 描述 |
|--------|------|
| `text` | 普通文本消息 |
| `image` | 图片消息 |
| `music` | 音频消息 |
| `pdf` | PDF文档消息 |
| `meme` | 表情包消息 |
| `gif` | GIF动图消息 |
| `code` | 代码片段消息 |

## 8. 消息状态枚举

| 状态值 | 描述 |
|--------|------|
| `sent` | 已发送 |
| `delivered` | 已送达 |
| `read` | 已读 |
| `edited` | 已编辑 |
| `recalled` | 已撤回 |
| `normal` | 正常（默认） |
